# Clean Action

把当前任务做到完整、直接、易于检查。把上下文消耗、工具往返、等待和返工一起计入完成成本，不以代码行数或单次调用数判断效率。

仅在用户手动调用时使用，作用于当前任务；任务完成或用户关闭后结束。继承已有授权与限制，不为使用本技能额外请求确认。用户只要求审阅执行方案时，给出精简后的方案，不开始实施。

## 执行前看一次整条路径

从验收者的角度确定：要得到什么结果，什么证据足以确认完成，哪些状态必须保留或恢复。已有答案直接复用，只查会改变下一步的缺失事实。

审视准备执行的步骤：

- **删掉**：省略后仍能满足任务、保护实际数据并验证结果的工作。不要把“可能有用”当作必要性。
- **合并**：已知且相互独立的读取、查询和验证一起完成；同一处修改尽量一次做完整。不要每发现一个文件、每改一行就交回用户或重跑全部检查。
- **保留顺序**：依赖上一步结果、共享可变状态、真实授权边界或不可逆操作的步骤。减少往返不等于盲目并行。
- **复用**：已有命令、工具、配置、证据和恢复路径。只有手动操作确实重复或容易出错时才写脚本；不为一次性任务建立通用框架。

路径清楚就执行，不输出审阅表、方案评分或逐条自我辩论。只有简化涉及用户需要决定的取舍时才解释。

## 按完整工作单元推进

每组操作完成一个可检查的结果，或回答一个会改变后续路径的未知问题。不要明知下一步可做却只挪一步，也不要把尚未知晓的步骤一次性做成大工程。

已有授权且委派确有收益时，把同一成果的实现、相关自测和结果摘要一并交付，提前给齐输入、写入边界和验收标准。主 Agent 集中验收，复用子任务有效证据，不重复实现或通读其全部过程；不要把同一成果拆成逐项派工与回报。

能独立运行的长任务交给执行器完成，优先等待完成通知或使用现有等待接口。确需轮询时只读轻量状态，不为进度沟通反复扫描全量数据。默认取完成摘要和异常，出现具体问题再展开相关日志；不为一次等待新建监控系统。

只在新证据改变路径时重新判断。备份、校验、隔离和回退针对具体风险，优先复用已有保护；已验证且未变化的事实不反复证明。不要每次工具调用前重跑本技能，也不默认增加审阅 Agent。

## 验收即停

执行足以发现相关失败的最小验证；证据必须能支撑实际结论。对同一产物先检查约定的主要用例，集中修正互不阻塞的问题，再构建和验证；阻断后续验收或威胁数据安全的问题及时处理。已有缺陷清单一次交齐，新增证据再补充，不要求预见所有问题。

修复后只重跑受影响的检查；共享行为变化或验收合同要求时再做全量验证。只更新受影响的产物，避免每次读取或局部修正都重建整套输出。保留必要的数据保护、错误处理和恢复工作，不以简洁为由缩减用户要求。

所需结果、必要验证和恢复均完成后停止。不追加清理、优化、额外测试、长报告或后续工程。交付当前结果、必要证据和实质未解决问题；内部操作经过仅在影响判断或用户要求时提供。
